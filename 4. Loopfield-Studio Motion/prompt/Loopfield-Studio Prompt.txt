# 역할
당신은 모션 디자이너 겸 크리에이티브 코더입니다. 첨부한 dataset/loopfield-studio-dataset.md로 25초 데이터 모션그래픽을 만듭니다. 슬라이드쇼나 기능 목록 나열이 아니라, 음악 박자에 맞춰 수식·프랙탈·기하 패턴·레이어·UI 오브젝트가 변형·이동하며 "수식 한 줄이 내 기기 안에서 4K 무한 루프 영상이 되기까지"를 한 문장으로 전달하는 영상이어야 합니다.
Loopfield Studio는 기하·프랙탈 패턴을 GLSL로 렌더링해 루프 영상을 만드는 웹 도구입니다. 그래서 이 영상은 이전 작품(SpaceX, Genesis, DJI)보다 그래픽 쪽에서 프랙탈과 기하 구성이 눈에 띄게 드러나야 합니다. 화면 전체를 셰이더 캔버스로 보고, 씬의 배경은 Loopfield 프리셋을 실제 GLSL로 렌더한 패턴으로, 전환은 라이브러리 패턴의 수학으로 만듭니다.

# 입력
- 주제: Loopfield Studio v1.1.0. 브라우저에서 돌아가는 WebGL 2 + GLSL 루프 영상 스튜디오. 프리셋 32종, 레이어 4장, 블렌드 5종, 팔레트 6종, @slider, 루프 경계 검사, 1080p~4K 출력, 계정·업로드·백엔드 없는 로컬 처리, 다섯 줄 함수로 시작하는 코드 모드
- 목적/타깃: 도구 소개 모션그래픽 / 심리스 루프가 필요한 모션·그래픽 디자이너, GLSL 입문~중급 개발자, VJ·숏폼 제작자, 업로드 없이 작업하려는 로컬퍼스트 창작자(데이터셋 15.1 주 타겟)
- 핵심 메시지: 수식 한 줄이 겹겹의 빛 무늬가 되고, 32가지 패턴과 네 장의 레이어, 여섯 팔레트, 슬라이더로 다듬어져, 끝과 처음이 맞물린 루프가 4K까지 계정도 업로드도 없이 내 기기 안에서 뽑힌다. 코드 다섯 줄이면 시작할 수 있다. 다음 무한 루프는 Loopfield.studio에서.
- 데이터: 첨부 파일(유일한 소스, 스냅샷 2026-10-01)
- 마무리: 도메인 "Loopfield.studio"가 크게 나타나는 엔드카드 + OG 문구 "Create your next infinite loop." + 스냅샷 날짜
- 브랜드 색/폰트: 아래 디자인 시스템(데이터셋의 기본 배경색, 테마색, 팔레트 값에서 가져옴)
- 언어: 헤드라인은 한국어, 마이크로 라벨은 영문 대문자. 셰이더 식별자(uPetals, pattern(vec2 p) 등)와 코드는 원문 그대로

# 데이터 규칙
- 모든 수치·날짜·사실은 첨부 파일에서만 가져옵니다. 파일에 없는 값은 만들지 않습니다.
- 마지막 도메인 "Loopfield.studio"는 사용자가 지정한 표기입니다. 데이터셋의 실행 주소는 https://jtech-co.github.io/Loopfield-Studio/이므로, 데이터 사용표에 출처를 "사용자 지정"으로 적습니다.
- 버전 표기: v1.0.0(프리셋 12종)과 v1.1.0(프리셋 32종, 20종 추가)은 모두 2026-09-22입니다. 2026-09-26 갱신은 "미출시 표기"이므로 버전 번호를 붙이지 않습니다.
- 검증 수치(12절)는 쓸 때마다 조건을 같이 적습니다.
  · 루프 경계 검사: 320×180, 표본 4장, 평균절대오차 ≤ 0.5/255, 32종 일치. "SAMPLE CHECK" 라벨을 붙이고, 데이터셋 원문대로 전 픽셀·전 시간 연속성 증명이 아니라는 점을 화면 라벨로 남깁니다.
  · 네이티브 인코딩 표본: 1920×1080, 24fps, 2초, 48프레임, avc1.640028, 약 5.7MB(2026-09-26). "~5.7 MB"로 씁니다.
  · 12.1의 테스트 환경(Chromium + SwiftShader)은 하드웨어 벤치가 아니므로, 속도·성능 주장으로 쓰지 않습니다.
- 쓰지 않는 값: 공개 별·포크 지표(0), 실사용자 수(데이터 없음), 기본 언어 문서 불일치(12.5), 4K PNG 실측 바이트(12.1 UI 내려받기와 12.2 실측이 서로 다른 시험이라 한 화면에 섞지 않음), 비교 대상 제품명(15.5).
- 장식용 HUD 숫자는 씬 번호, 박 카운터, 타임라인에서 계산한 전역 위상(uLoop = t ÷ 25)처럼 파일 사양이나 타임라인에서 파생된 값만 씁니다. 가짜 FPS 카운터·GPU 사용률·렌더 시간 같은 성능 수치는 금지합니다.
- 프리셋 셰이더는 Loopfield Studio 저장소(js/presets.js, js/presets-extra.js, MIT, JTech Co.)의 GLSL을 옮겨 씁니다. 화면에 보이는 슬라이더 값과 범위는 데이터셋 5절 슬라이더 스펙 값만 씁니다. 코드 모드 씬에 타이핑되는 starter 소스는 저장소 원문 그대로 씁니다.

# 사양
- 1920×1080, 30fps, 25초, 120 BPM (1박 = 0.5초 = 15프레임)
- 1씬 = 4박(2초), 총 12씬. 12번 씬은 6박(3초)으로 남는 시간을 흡수합니다.
- 시간 계층: 씬=4박 / 핵심 이벤트=1박 / 반복 사이클=16분음표 / 몽타주 컷=8분음표
- 전환은 박 3~5프레임 전에 시작해 박에 착지합니다. 박→프레임 변환은 누적 오차가 없는 함수로 계산합니다. BPM과 전환 타이밍은 이전 작품과 같게 두고, 전환 기법과 분위기만 달리합니다.

# 무드와 그래픽 언어
SpaceX·Genesis는 "무대 위 데이터 오브젝트의 변형", DJI는 "풍경 위를 나는 카메라"였습니다. 이 작품은 "화면 전체가 셰이더 캔버스"입니다.
- 셰이더 캔버스: 씬마다 Loopfield 프리셋 하나가 화면을 채우거나(풀블리드), 원·타일·레이어 판 같은 기하 창 안에서 돕니다. 패턴은 uAngle·uCycle 위상으로 움직여 각 씬 안에서도 끊김 없는 루프를 그립니다.
- 작도선: 패턴이 채워지기 전에 가는 선으로 축, 동심원, 대칭축, 격자, 타일 경계가 먼저 그려집니다(스트로크 드로잉). 기하 구성이 눈에 보이게 하는 장치이며, 작도선 옆 숫자는 데이터셋 값(예: uPetals 7 → 7-FOLD)만 씁니다.
- 프랙탈: 망델브로 반복 횟수 증가, 줄리아 궤도, 만화경 접힘, 시에르핀스키 분할을 씬과 전환에 고르게 씁니다.
- 전환: 라이브러리 패턴의 수학으로 만든 GLSL 전환 셰이더입니다. 프랙탈 줌, 만화경 접기, 트루셰 타일 회전, 블렌드 스윕, 극좌표 펼치기, 도메인 워프, 로그 나선 소용돌이, 해상도 단계, 보로노이 파쇄, 육각 펄스, 시에르핀스키 분할 중에서 씬마다 하나씩, 중복 없이 씁니다.
- 이전 작품에서 쓴 기법(연도 롤러, 도장, 링 게이지, 스트립 셔터, 링 버스트, 아이리스, 슬라이스 글리치, RGB 색수차, 모션블러 슬라이드, 클록 와이프, 카메라 워크 전환, 풍경 패럴랙스, 뷰파인더 HUD)은 다시 쓰지 않습니다.

# 데이터→비주얼 매핑
- 핵심 수식(망델브로 프리셋 uIterations[48–384]=160) → 복소평면 작도선 위에서 반복 횟수가 16분음표마다 두 배가 되며 집합이 드러남, 160에서 정지
- 기본 프리셋(3절: 신규 세션 기본 Prism Bloom, 5절 uPetals 7 · uBands 9 · uTwist 1.2, 코드 473자, 슬라이더 3) → 7개 대칭축 작도선 위로 피어나는 프리즘 블룸
- 프리셋 수(5절: v1.0.0 12종 → v1.1.0 32종, 분류 기하 13 · 유기 8 · 프랙탈 6 · 볼륨 4 · 코드 1, 슬라이더 합계 70) → 32칸 콘택트 시트(각 칸이 실제 프리셋 렌더), 16분음표로 점등 + 분류 누적 막대
- 레이어와 블렌드(1절 F02·F03: 최대 4장, normal · screen · add · multiply · difference / 3절 새 레이어 기본 Screen / 11절 예제 01 「겹쳐지는 궤도」: prism normal 1 + orbital screen 0.28 · 회전 20 · 위상 0.12) → 원근으로 펼친 레이어 판 4장이 박마다 쌓였다가 한 장으로 합쳐짐
- 팔레트(4절: 6종 × 3색 = 18색, 오로라 · 일몰 · 빙하 · 아날로그 · 캔디 · 모노) → 6분할 원판에 같은 패턴이 팔레트별로 칠해지고 색조(uHue) 회전
- 슬라이더(1절 F06·F07: @slider 문법, 레이어당 16개 / 5절 rose uPetals[2–12]=5) → 슬라이더 손잡이가 16분음표로 움직이며 장미 곡선의 꽃잎 수가 실시간으로 바뀜
- 루프(2.2절: 마지막 위상 (N−1)/N, 위상 1 중복 프레임 없음 / 12.4절: 표본 4장, 32종 일치 / 5절 julia uReal −0.745 · uImag 0.185 · uOrbit 0.028) → 상수 c가 닫힌 원 궤도를 한 바퀴 돌아 제자리로, 위상 링, 처음과 끝 프레임을 difference로 겹치면 검정(MATCH)
- 출력(2.1·2.2·2.3절: 1080p · DCI 2K · QHD · UHD, 출력 조합 10쌍, 24 · 30 · 60fps, 2–60초, 최대 3,600프레임, 비트레이트 상한 180 Mbps) → 실제 비율로 그린 해상도 프레임이 박마다 커지고, 프레임 안 패턴 밀도도 함께 커짐
- 로컬퍼스트(1절 F30·F36, 14절: 계정 · 백엔드 · 업로드 · 추적 스크립트 0 / 12.5절 네이티브 인코딩 표본) → 기기 라인아트 안에서 레이어 → WebGL 2 → WebCodecs H.264 → MP4로 흐르고, 바깥의 계정·서버·업로드 아이콘에 0이 찍힘
- 코드 모드(1절 F23 분할 기본 56% / 5절 starter 190자 · 슬라이더 1 · "다섯 줄 함수" / 6절 pattern(vec2 p), 소스 48,000자) → 56:44로 나뉜 편집기에 starter가 타이핑되고, 컴파일되면 미리보기에 동심 물결이 켜짐
- 같은 데이터가 다시 나올 때는 형식을 바꿉니다(예: 32 = 콘택트 시트 → 몽타주 대형 숫자 → 엔드카드 서브카피, 4K = 해상도 프레임 → 몽타주 숫자 → 엔드카드 서브카피, 계정 0 = 기기 다이어그램 → 몽타주 숫자 → 엔드카드 서브카피, 루프 = 줄리아 궤도 → 몽타주 32/32 → 마지막 HUD 위상 (N−1)/N).

# 프리셋 비주얼
도구 소개 영상이므로, 모션그래픽 스타일이어도 화면 속 패턴이 Loopfield의 어떤 프리셋인지 알아볼 수 있어야 합니다.
- Loopfield 저장소의 프리셋 썸네일(assets/presets/*.webp, 320×180 실제 GLSL 렌더)과 소스를 보고 프리셋별 시각 특징을 정리한 뒤, 같은 GLSL을 영상의 WebGL 2 렌더러로 옮겨 그립니다. 썸네일과 스크린샷 이미지 파일은 저장소에 넣지 않습니다.
- 공용 함수(rotate, palette, hash21, noise2, fbm, stroke)와 유니폼 의미(uLoop, uAngle, uCycle, uColorA/B/C, uHue)는 데이터셋 6절의 GLSL API v1과 같게 맞춥니다.
- 패턴 색은 데이터셋 4절 팔레트 값으로 칠합니다. 블룸은 앱 기본값(0.35) 이하로만 씁니다. 텍스트와 UI에는 글로우를 쓰지 않습니다.
- UI 모티프(레이어 타일, 슬라이더, 팔레트 칩, 코드 편집기, 재생 트랜스포트)는 Loopfield 화면 캡처의 구조를 참고해 우리 디자인 시스템으로 다시 그립니다. 앱 화면을 그대로 복제하지 않습니다.
- 로고: Loopfield의 궤도 로고(assets/favicon.svg: 서로 ±35° 기운 타원 두 개 + 가운데 원 + 작은 점)를 엔드카드에서 작도선처럼 그려 보입니다. 사용자 소유 브랜드이므로 사용하되, 다른 회사의 로고는 쓰지 않습니다.

# 모션 규칙
- 등장은 back/spring 오버슈트, 퇴장은 expo.in, 스태거 40~80ms
- 씬마다 시그니처 모션 1개. 전환 기법은 서로 중복하지 않습니다.
- 가능한 전환은 매치 컷으로 처리합니다(카디오이드의 검은 안쪽 → 프리즘 중심, 접힌 타일 → 콘택트 시트, 원판 → 슬라이더 트랙, 줄리아 소용돌이 → 해상도 프레임 등).
- 카운터는 목표값에서 정확히 멈춘 뒤 최소 1박 유지합니다.
- 어떤 요소도 1박 이상 완전히 정지하지 않습니다(패턴 위상 루프, 작도선 회전, 미세 스케일).
- 셰이더 패턴은 uAngle(= TAU × 위상)과 uCycle로 움직여, 씬 안에서도 위상이 한 바퀴 돌면 처음과 같은 모양으로 돌아옵니다.

# 금지
- 불릿·표 화면, 한 화면에 3문장 이상, 데이터 전체 동시 노출
- 페이드만으로 된 전환, 음악과 무관한 타이밍
- 파일에 없는 수치, 가짜 성능 수치, 다른 회사 로고, 정의가 다른 검증 수치를 조건 없이 섞어 쓰기
- 이전 작품의 전환 기법과 연출 장치 재사용

# 기술 요구 (저장소 규칙: 1. SpaceX Motion 구조를 따름)
- index.html + css/ + js/로 분할합니다. 하나의 거대한 파일로 만들지 않습니다. 씬은 js/scenes/NN-<역할>.js로 씬당 파일 하나.
- 외부 의존성 금지(CDN, 웹폰트 CDN, npm 런타임). 일반 <script defer> + 전역 네임스페이스로 짜서 file://과 GitHub Pages에서 바로 재생되게 합니다.
- 1920×1080 무대를 고정하고 뷰포트에 맞춰 scale합니다.
- render(t)가 모든 상태를 t로부터 계산합니다(실시간 타이머 의존 금지, 랜덤은 시드 고정). window.seek(t)를 노출합니다. 셰이더 유니폼도 전부 t에서 계산합니다.
- WebGL 2 렌더러는 js/fx/에 둡니다(공용 GLSL 헤더, 프리셋 셰이더 문자열, 프로그램·FBO 관리). 씬의 GL 결과는 텍스처로 받아 전환 셰이더가 두 씬을 합성합니다. 선화·UI 목업은 SVG/DOM 또는 canvas 2D로 그리고, 헤드라인·캡션·라벨·HUD는 DOM으로 둡니다. 캔버스는 preserveDrawingBuffer로 만들어 캡처에 그대로 잡히게 합니다.
- 32칸 콘택트 시트처럼 패턴이 많은 씬은 한 GL 캔버스에서 뷰포트를 나눠 그립니다.
- 파일에서 옮긴 값은 js/data.js의 DATA 한 곳에 모으고, 모든 씬은 DATA만 참조합니다. 프리셋 GLSL과 팔레트 값은 js/fx/의 셰이더 모듈에 모읍니다.
- WebGL 2가 없는 브라우저에서는 대체 문구를 보여 줍니다(Loopfield와 같은 요구 조건).
- 오디오: WebAudio로 120 BPM 트랙을 생성합니다.
  · 기본: 킥 1·3박, 클랩 2·4박, 하이햇 8분음표, 서브 드론, 리사주 3:4 비율(5절 lissajous 기본값)로 고른 아르페지오
  · 패턴 수학 전환: 박 직전 필터 스윕 + 전환마다 다른 짧은 신스 제스처(줌 상승 글라이드, 접힘 클릭, 타일 틱 등)
  · 01번: 반복 횟수가 두 배가 될 때마다 음이 한 단계씩 오르는 16분음표 틱
  · 03번: 프리셋이 켜질 때마다 오르는 블립(12개 + 20개)
  · 06번: 슬라이더 손잡이를 따라가는 지퍼음
  · 07번: 같은 두 박 모티프가 정확히 반복되고 b3 MATCH에 차임
  · 08번: 해상도 단계마다 오르는 음
  · 10번: 타이핑 클릭과 컴파일 순간의 짧은 상승음
  · 11번: 하이햇 16분음표로 밀도 상승
  · 12번 씬 b5: 마지막 히트 + 리버브 꼬리
  · 같은 트랙을 OfflineAudioContext로 WAV 렌더하는 함수도 제공합니다.
- 컨트롤: 재생/정지, 스크럽 바, 박 그리드 오버레이 토글, 씬 점프
- 렌더: tools/render.mjs(NAME = loopfield-studio)로 t=i/30마다 seek → 캡처하고, WAV와 함께 ffmpeg로 out/loopfield-studio.mp4를 출력합니다. 대표 장면으로 out/poster.jpg를 뽑습니다.
