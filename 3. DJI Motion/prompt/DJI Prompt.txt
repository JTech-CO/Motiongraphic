# 역할
당신은 모션 디자이너 겸 크리에이티브 코더입니다. 첨부한 dataset/DJI_dataset_2006-2026.md로 25초 데이터 모션그래픽을 만듭니다. 슬라이드쇼나 인포그래픽 나열이 아니라, 음악 박자에 맞춰 제품 실루엣·풍경·레이더·경로·데이터 오브젝트가 변형·이동하며 "부품 회사가 하늘을 거쳐 손 안까지 온 20년"을 한 문장으로 전달하는 영상이어야 합니다.
DJI는 드론과 영상 장비를 만드는 회사이므로, 이 영상은 이전 작품(SpaceX, Genesis)보다 그래픽 쪽에서 속도·활공·촬영·풍경의 감각이 살아 있어야 합니다. 화면 전체가 드론으로 찍은 한 번의 비행처럼 느껴지게 하고, 전환은 카메라 워크(크레인, 틸트, 다이브, 초점 이동, 셔터)로 만듭니다.

# 입력
- 주제: DJI 2006–2026. 비행제어기 부품으로 창업, 팬텀으로 컨슈머 드론 대중화, 드론 시장 장악, 플래그십 성능 진화, 249g 미니, 핸드헬드 카메라 확장과 액션캠 역전, 매출 성장, 미국 규제까지
- 목적/타깃: 데이터 모션그래픽 쇼케이스 / 드론·카메라·테크 산업과 데이터에 관심 있는 한국어권 시청자
- 핵심 메시지: 2006년 선전에서 비행제어기 부품으로 시작한 DJI는 팬텀으로 하늘을 열어 하늘에서 잡히는 드론 열에 여덟을 차지했고, 249g 미니와 손 안의 카메라로 영역을 넓혀 매출 약 115억 달러에 이르렀지만, 미국은 신제품의 문을 닫았다. 그래도 DJI의 카메라는 하늘에서 손 안까지 와 있다.
- 데이터: 첨부 파일(유일한 소스)
- 마무리: "DJI 2006—2026" 텍스트 타이틀 + 데이터 기준일
- 브랜드 색/폰트: 아래 디자인 시스템에서 직접 설계(공식 브랜드 자산은 쓰지 않음)
- 언어: 헤드라인은 한국어, 마이크로 라벨은 영문 대문자

# 데이터 규칙
- 모든 수치·날짜·사실은 첨부 파일에서만 가져옵니다. 파일에 없는 값은 만들지 않으며, 표에 없는 연도·월은 비워 둡니다.
- 아래 씬 초안의 수치는 작성 시점의 스냅샷입니다. 첨부 파일 값과 다르면 파일 값으로 교체하고 카피도 그에 맞게 고칩니다.
- DJI는 비상장사입니다. 매출·출하량은 공시가 아니라 언론·위키·조사업체 추정치이므로, 화면에 쓸 때 "EST." 라벨을 붙이고 숫자 앞에 "~"(헤드라인에서는 "약")를 붙입니다.
- 매출(T03)은 출처가 비교적 분명한 점만 씁니다: 2011 ~$4.2M, 2013 ~$131M, 2014 ~$0.5B, 2015 ~$1B, 2025 ~$11.5B(CNY 80B). 품질 플래그가 low–medium인 2016~2024 구간 추정치로 연속 시계열을 그리지 않습니다. Craft.co 2022 USD 21.4B는 이상치이므로 쓰지 않습니다.
- 매출 규모가 네 자릿수 넘게 차이 나므로 매출 차트는 로그 눈금으로 그리고 "LOG SCALE"을 표기합니다.
- 점유율(T05·T06)은 정의가 제각각입니다(매출 / 대수 / 탐지 / Remote ID). 모든 점유율 값에는 지표·지역·기간·출처 라벨을 함께 붙이고, 정의가 다른 값을 한 축이나 한 시계열에 놓지 않습니다. 파일의 mermaid 차트처럼 정의가 섞인 막대를 재현하지 않습니다.
- 구성비는 합이 100이 되는 단일 출처 표만 도트·그리드로 그립니다(예: 2025 Dedrone 탐지 83.48 / 9.82 / 1.40 / 5.30). 도트 수로 나눌 때는 최대 잉여 방식으로 반올림하고 라벨은 원문 값을 씁니다.
- 부등호가 붙은 값(>5,000,000, <25 등)은 부등호를 살려 "5,000,000+", "<25%"처럼 씁니다. 범위 값은 범위 그대로 쓰거나(30–40만), 파일의 대표값을 씁니다.
- 쓰지 않는 값: 2026 CNY 100B 매출 목표, DJI 주장값(2026 차단 25종·美 매출 USD 1.56B 손실), IPO 루머, FAA 등록 대수(DJI 출하가 아님), 시장 규모 분모(출처 간 불일치), 순이익 2024 추정(미검증).
- 장식용 HUD 숫자는 연도·경과 연수·씬 번호·박 카운터·타임라인에서 계산한 타임코드처럼 파일이나 타임라인에서 파생된 값만 씁니다. 촬영 화면처럼 보이는 고도·속도·배터리·거리 같은 가짜 텔레메트리는 금지하고, 비행·카메라 관련 수치는 파일의 스펙 표(T07·T10·T11) 값만 씁니다(예: 초점거리 라벨은 T11의 28mm·168mm만).
- DJI·Hasselblad·Osmo·Ronin·GoPro·Insta360의 로고와 워드마크를 재현하지 않습니다. 이름은 우리 폰트의 일반 텍스트로만 씁니다. 경쟁사 제품은 그리지 않고 이름 라벨만 씁니다.

# 사양
- 1920×1080, 30fps, 25초, 120 BPM (1박 = 0.5초 = 15프레임)
- 1씬 = 4박(2초), 총 12씬. 12번 씬은 6박(3초)으로 남는 시간을 흡수합니다.
- 시간 계층: 씬=4박 / 핵심 이벤트=1박 / 반복 사이클=16분음표 / 몽타주 컷=8분음표
- 전환은 박 3~5프레임 전에 시작해 박에 착지합니다. 박→프레임 변환은 누적 오차가 없는 함수로 계산합니다. BPM과 전환 타이밍은 이전 작품과 같게 두고, 전환 기법과 분위기만 달리합니다.

# 무드와 촬영 언어
이전 작품이 "데이터 오브젝트가 무대 위에서 변형"되는 방식이었다면, 이 작품은 "카메라가 풍경 위를 날며 데이터를 찍는" 방식입니다.
- 풍경: 시드 고정 능선 3~4겹, 등고선, 수평선, 평면 구름층, 단색 해 원반으로 만든 플랫 풍경. 같은 색의 명도 차만으로 원근(공기 원근)을 표현하고, 씬마다 시간대(새벽 · 낮 · 안개 · 황혼 · 밤)가 바뀌는 한 번의 비행처럼 이어집니다.
- 활공: 카메라는 멈추지 않고 앞으로 흐릅니다. 가까운 층일수록 빠른 패럴랙스, ±2° 이내의 완만한 뱅크, 호버링 중인 제품의 미세한 상하 움직임.
- 속도: 방향성 스피드 스트릭, 하이퍼랩스처럼 늘어나는 빛 궤적, 전환 순간의 원근 모션 라인.
- 촬영: 뷰파인더 코너 브래킷, 3분할 가이드, 초점 브래킷, ● REC와 타임코드, 2.39:1 레터박스, 초점 이동(랙 포커스), 셔터 플래시.
- 전환: 카메라 워크로 만듭니다. 크레인 업, 틸트 업, 피치 다운(버드아이), FPV 다이브, 랙 포커스, 셔터 캡처, 하이퍼랩스, 오빗, 구름 통과, 줌 스텝, 짐벌 수평 와이프 중에서 씬마다 하나씩, 중복 없이 씁니다.
- 이전 작품에서 쓴 기법(연도 롤러, 도장, 링 게이지, 스트립 셔터·링 버스트·아이리스·슬라이스 글리치·RGB 색수차·모션블러 슬라이드·클록 와이프)은 다시 쓰지 않습니다.

- 핸드헬드 스마트캠 출하 점유(T06: IDC Q2 2026 DJI 73%) → 별도 라벨 칩(액션캠 매출과 정의가 다르므로 같은 축에 두지 않음)

# 제품 실루엣
제품 회사 영상이므로, 모션그래픽 스타일이어도 화면 속 제품이 무엇인지 적어도 구분할 수 있어야 합니다.
- 공식 스펙 페이지의 치수와 공식 제품 사진으로 제품별 디자인을 조사한 뒤, 그 비례(바디 폭·높이, 암 길이와 각도, 프로펠러 지름, 짐벌·카메라 위치와 크기, 랜딩기어, 화면 위치)를 측정해 SVG path로 단순화합니다. 사진이나 이미지 파일은 저장소에 넣지 않습니다.
- 드론은 정면 또는 3/4 정면을 기본으로 하고, 아이콘처럼 작게 쓸 때는 X자 암이 보이는 탑뷰를 씁니다. 핸드헬드는 정면을 씁니다.
- 조사한 제품별 식별 포인트
  · 초기 비행제어기(2006): 특정 실물 재현이 아니라 PCB + 센서 박스 + 핀 헤더로 "부품"임을 보여 주는 모듈
  · Phantom 1(2013, 대각 350 mm, 350×350×190 mm): 흰색 셸 바디, 은색 모터가 달린 X자 4암, 앞쪽 두 암의 빨간 방향 띠, 흰 프로펠러, 곧게 내려온 두 개의 랜딩기어, 바디 아래 외장 카메라 마운트
  · Mavic 4 Pro(2025, 펼침 328.7×390.5×135.2 mm): 다크 그레이 바디, 앞 암은 위에서 앞으로·뒤 암은 아래에서 뒤로 뻗는 X자 배치, 검은 프로펠러, 정면 하단의 둥근 카메라 헤드 안 렌즈 3개(큰 메인 1 + 작은 망원 2), 정면 센서 창
  · Mavic Mini(2019, 펼침 160×202×55 mm): 밝은 회색의 작고 둥근 바디, 가는 암, 정면 하단의 작은 짐벌 카메라
  · Mini 5 Pro(2025, 펼침 304×380×91 mm): 회색 바디, 정면 하단에 바디 폭의 절반 가까이 되는 큰 1" 카메라 짐벌, 위쪽 센서 창
  · Osmo Pocket(2018, 121.9×36.9×28.6 mm): 검은 막대 그립, 위의 3축 짐벌 헤드(요크 + 작은 사각 카메라), 그립 위쪽의 작은 정사각 화면과 둥근 버튼 2개
  · Osmo Pocket 3(2023, 139.7×42.2×33.5 mm): 더 두꺼운 그립과 더 큰 둥근 렌즈 헤드, 가로로 돌리면 그립보다 넓게 튀어나오는 2인치 화면, 화면 아래 조이스틱과 빨간 링 녹화 버튼

# 모션 규칙
- 등장은 back/spring 오버슈트, 퇴장은 expo.in, 스태거 40~80ms
- 씬마다 시그니처 모션 1개. 씬 초안의 전환 기법은 서로 중복하지 않습니다.
- 가능한 전환은 매치 컷으로 처리합니다(이전 씬의 오브젝트가 다음 씬의 주인공이나 배경이 됨).
- 카운터는 목표값에서 정확히 멈춘 뒤 최소 1박 유지합니다.
- 어떤 요소도 1박 이상 완전히 정지하지 않습니다(풍경 패럴랙스, 호버링 보브, 미세 스케일).
- 카메라 워크 전환은 가속(expo.in) → 박 착지 순간 감속(expo.out)으로, 실제 짐벌·드론 촬영처럼 부드럽게 멈춥니다.

- 이전 작품의 전환 기법 재사용

# 기술 요구 (저장소 규칙: 1. SpaceX Motion 구조를 따름)
- index.html + css/ + js/로 분할합니다. 하나의 거대한 파일로 만들지 않습니다. 씬은 js/scenes/NN-<역할>.js로 씬당 파일 하나.
- 외부 의존성 금지(CDN, 웹폰트 CDN, npm 런타임). 일반 <script defer> + 전역 네임스페이스로 짜서 file://과 GitHub Pages에서 바로 재생되게 합니다.
- 1920×1080 무대를 고정하고 뷰포트에 맞춰 scale합니다.
- render(t)가 모든 상태를 t로부터 계산합니다(실시간 타이머 의존 금지, 랜덤은 시드 고정). window.seek(t)를 노출합니다.
- 풍경(능선·구름·등고선)은 공용 모듈 하나에서 시드로 생성해 씬마다 시간대 색만 바꿔 씁니다. 카메라 워크 전환(피치·틸트·오빗)은 CSS 3D 변환 또는 canvas 원근 변환으로 구현합니다.
- 1,000개 레이더 도트·400개 편대 아이콘처럼 요소가 많으면 canvas, 나머지는 SVG/DOM으로 그립니다.
- 파일에서 옮긴 값은 js/data.js의 DATA 한 곳에 모으고, 모든 씬은 DATA만 참조합니다. 제품 실루엣은 js/ui/에 제품별 사양으로 모읍니다.
- 오디오: WebAudio로 120 BPM 트랙을 생성합니다.
  · 기본: 킥 1·3박, 클랩 2·4박, 하이햇 8분음표, 서브 드론, 필터 노이즈로 만든 바람 소리 층(활공)

  · 02·05번: 로터 스핀업(블레이드 통과 주파수로 진폭 변조한 버즈 + 피치 상승)

  · 10번: 제한 구역이 생길 때마다 저역 임팩트
  · 11번: 하이햇 16분음표로 밀도 상승
